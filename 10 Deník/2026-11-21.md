## M4 Aktualizace jedním klikem (pozdě večer)
Orchestrace `scraper update` + `aktualizuj.bat` + `/status` + `add-price`:
- `scraper/orchestrate.py` — single entry point `run_update(cfg, only_store, force)`. Projede seřazené aktivní obchody (`is_active = true`). Per obchod: skip pokud dneska úspěšně běžel (pokud není `--force`), skip pokud chybí parser v `REGISTRY` (poznámka „no parser"), otevře scrape_run, stáhne `fetch()`, stage_items, sanity check, finish_run (`ok`/`partial`/`failed`). Po všech obchodech: `merge_prices` nad všemi úspěšnými runy, `refresh_materialized_view`, `cleanup_staging`, `POST /api/revalidate` s tokenem (ignoruje silent pokud URL/token chybí).
- Sanity check: `percentile_cont(0.5) within group (order by items_found)` nad posledními 7 OK běhy téhož obchodu; dnes stažených položek < 50 % mediánu → `status = partial`. Při prvním běhu (žádná historie) vždy `ok`.
- `BlockedError` (401/403/429) → `failed` s poznámkou „blokováno: …". Jiný exception → `failed` s plným `traceback` v `scrape_run.error`.
- Souhrnná tabulka přes `rich.table.Table` — obchod, status (OK/PARTIAL/CHYBA/SKIP s barevnými tagy), položek, změn, trvání (M:SS), poznámka. Kopíruje layout z [[05 Scraper/Aktualizace dat]].
- `__main__.update`: `_write_log_file()` přidá `FileHandler` do `scraper/logs/YYYY-MM-DD_HHMM.log`; exit code 0 (vše OK) / 1 (někde `failed`).
- `aktualizuj.bat` v kořeni repa: `cd /d "%~dp0scraper"`, routing `review` / `add-price` / default `update`; `pause` na konci. Předává `%*` pro další argumenty (`--force`, `--store lidl`).
- `__main__.add_price`: interaktivně vybere produkt (fuzzy přes `pg_trgm % f_norm()`), přidá `price_source='manual'` row (SCD2 close → insert). Pokud `store_product` v daném obchodě neexistuje, vytvoří syntetický s `store_sku='manual-<product_id>'`.
- `/status` stránka: `fetchStatus()` pulls per obchod poslední scrape_run přes `LEFT JOIN LATERAL`. Tabulka: obchod, status badge (barevný per OK/PARTIAL/CHYBA/RUN), položek, změn, relativní čas „před N h", trvání, poznámka (přetéká s tooltipem).

## M5 Další zdroje + párování (večer)

**Matcher refactor (`scraper/matching/matcher.py`)**
- Vytvoření samostatného modulu z dřívější in-staging logiky. Veřejné API: `match_candidates(conn, candidates)` vrací `MatchOutcome` na každý vstup.
- Kaskáda: 1) EAN → auto-accept; 2) same brand + volume + token_set_ratio == 100 na `match_norm` → `exact_norm`; 3) stejné ≥ 90 → `fuzzy` auto-accept; 4) 75–90 → `match_candidate` pending; 5) nic → new `product` (per M5 fallback stejný jako M2).

## M5 — oprava po prvním živém běhu Tesca (15:16–15:25)
